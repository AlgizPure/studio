## Фаза 2: Создание All_Project_rules.md

### 2.1 Структура мастер-файла правил

Создать файл `02_PROJECT_STRUCTURE/AI_INSTRUCTIONS/All_Project_rules.md` со следующей структурой:

```markdown
# All Project Rules - Проектные Правила для Всех Файлов

## Как использовать этот файл
1. Скопируйте нужные правила в .cursor/rules/
2. Каждое правило - отдельный файл
3. Cursor автоматически применит правила при триггерах

## Оглавление
[Список всех правил с ссылками]

---

## RULE_01: metadata.yaml
### Файл: 00_RAW_DATA_TEMPLATE/metadata.yaml
### Триггеры
[детальное описание]

## RULE_02: PROJECT_ESSENCE.md
[и так далее для каждого файла]
```

### 2.2 Создание индивидуальных правил

Для КАЖДОГО файла создать правило с секциями:

- **Активация в начале**: "👀 ACTIVE: [RULE_NAME]"
- **Триггеры**: когда правило срабатывает
- **Проверки**: что проверяем перед обновлением
- **Действия**: что конкретно обновляем
- **Зависимые файлы**: какие файлы тоже могут требовать обновления
- **Не трогать**: что вне зоны ответственности
- **Уведомление в конце**: "✅ [RULE_NAME]: обновлены [файлы] по триггеру [X]"

## Фаза 3: Обновление BOOTSTRAP_START_PROMPT.md

### 3.1 Удаление "выходов" из промптов

Найти и заменить все фразы:

- ❌ "можешь оставить как template" → ✅ "ОБЯЗАТЕЛЬНО заполни полностью"
- ❌ "при необходимости" → ✅ "ВСЕГДА"
- ❌ "если нужно" → ✅ "ОБЯЗАТЕЛЬНО"
- ❌ "можно заполнить позже" → ✅ "заполни СЕЙЧАС"

### 3.2 Добавление механизма полного извлечения функций

В PHASE 1 (ANALYSIS) добавить:

```markdown
### Task 1.2.1: ПОЛНОЕ извлечение всех функций

**ОБЯЗАТЕЛЬНО:**
1. Прочитай ВСЕ чаты, документы, заметки
2. Извлеки КАЖДУЮ упомянутую функцию/фичу
3. Создай полный список (как в Ground Control: 150+ функций)
4. Группируй по модулям
5. НИЧЕГО НЕ УПУСКАЙ - каждое упоминание функционала важно

**Формат извлечения:**
- Категория A: [список функций]
- Категория B: [список функций]
- ... для всех категорий

**Проверка полноты:**
- Пройдись по каждому чату повторно
- Убедись что все функции извлечены
- Если в чате 150+ функций → в списке должно быть 150+
```

### 3.3 Усиление PHASE 5 (DOCUMENTATION GENERATION)

Добавить жесткие требования:

```markdown
### PHASE 5: DOCUMENTATION GENERATION - СТРОГИЕ ТРЕБОВАНИЯ

**MODULES_REQUIREMENTS:**
ОБЯЗАТЕЛЬНО создать файл для КАЖДОГО модуля:
- Используй extracted_features из PHASE 1
- Для каждого модуля: перечисли ВСЕ его функции
- НЕ создавай "групповые" requirements
- НЕ пропускай функции

**Формат module_requirements.md:**
[шаблон с обязательными секциями]

**ПРОВЕРКА:**
Количество функций в requirements = количество в extracted_features
```
